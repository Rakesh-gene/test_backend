# GAP-005: Trace context, load and recovery

Recorded 7 November 2026. GAP-005.1 is fixed and verified on Windows x64. GAP-005.2
and GAP-005.3 remain open. This report does not close the whole P12 qualification gate.

## Problem and resulting behavior

Previously, runner requests started unrelated root traces and background job logs
needed explicit span arguments to correlate. The CLI now opens a command span and
accepts an upstream W3C carrier from `TRACEPARENT`/`TRACESTATE`. Authenticated runner
requests carry bounded `traceparent`/`tracestate` fields after capability negotiation.
The runner extracts the parent and creates a server span; a background job creates
its own child span even after the start-request response has returned.

Node async-local context isolates concurrent requests/jobs without replacing a host
application's global OpenTelemetry context manager. Logs infer the active span and
durable tool events record the same `trace_id`/`span_id`. Job spans include job/root
and optional tree IDs; failed/cancelled jobs have error status. CLI logging does not
add output to JSON stdout or the interactive terminal; configured OTLP still works.

Only W3C trace headers cross IPC. Baggage is not accepted. Oversized carriers fail
the contract, invalid W3C values are ignored by the official OTel propagator, and
authentication is checked before processing the request context. Older peers omit
the propagation capability; clients keep their original request shape with them.

This covers Kode's current CLI/IPC/background-job boundaries. Child command or
provider internals need explicit instrumentation in later adapters; their own spans
are not implied by a Kode job span. Automatic crash/native-session reconciliation
and P12 sustained-load qualification remain separate items.

## Verification

`node node_modules/vitest/vitest.mjs run tests/tracing.test.ts --reporter=verbose`
exits zero with three passing scenarios:

1. Nested/concurrent async context isolation, invalid/zero headers, tracestate,
   bounded carriers and rejected baggage.
2. Two real CLI processes with distinct upstream traces attach to a real runner.
   A local OTLP receiver verifies CLI → RPC → job parent IDs, server span kind,
   matching durable event/log IDs, concurrent isolation and redacted sinks.
3. A legacy IPC peer without the capability receives the original request shape.

`.artifacts/GAP-005-trace-context.json` retains the synthetic exported chains and
assertion summary. Full regression results are in `.artifacts/verification.json`
and `.artifacts/vitest.json`: build/typecheck, lint, all 29 integration tests, real
PTY interaction and JSON doctor pass with empty stderr on this host. The three-OS workflow includes these tests, but remote
macOS/Linux runs have not occurred. Source/evidence hashes identify the local run.

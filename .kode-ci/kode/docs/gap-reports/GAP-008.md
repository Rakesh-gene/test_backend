# GAP-008: Native dependency and SDK/configuration qualification

Implemented 8 November 2026 for native npm/PackageReference environments on the
qualified Windows x64, Linux x64 and macOS arm64 baseline. Broader release architecture
coverage remains GAP-004/P13. Container dependency receipts are explicitly unsupported
and cannot adopt a native ready receipt (see GAP-007).

The environment identity now resolves the repository's selected PATH/environment,
manager executable and version rather than the harness's runtime alone. npm identity
includes the actual selected Node runtime/ABI, npm.cmd's sibling Node on Windows,
and the selected validator runtime. Validators inherit preparation environment with
their own overrides. Effective npm configuration, explicit user/global config files,
NuGet ancestor/user/machine/explicit configs and relevant SDK/compiler environment
settings contribute hashes. Configuration contents and credential values are not
persisted. SDK selection runs from the declared preparation cwd, respecting global.json.

An existing installation is reusable only after manager metadata/health checks and
any required native validator succeed under the selected runtime. A native addon
requires a declared validator that actually loads/exercises it. Corruption, an ABI
change or SDK/configuration change cannot reuse the ready receipt. User-owned
installations remain untouched; necessary preparation uses a task tree. Interrupted
preparation stays unready and is not retried blindly.

`tests/environment-qualification.test.ts` records:

- `.artifacts/GAP-008-native.json`: a real copied SQLite native addon executes a
  query, healthy reuse performs zero installations, a corrupted binary is rejected,
  a real alternate Node ABI fails to load it, external npm config changes invalidate
  reuse and source lock/binary preservation is checked.
- `.artifacts/GAP-008-sdk.json`: actual selected .NET SDK, ancestor/explicit NuGet
  configuration invalidation, selection of a second installed SDK producing a new
  unready identity, and unavailable pinned SDK rejection before dispatch.

Native CI supplies Node 24.22.1 and Node 25.0.0 (ABIs 137 and 141), plus SDKs 10.0.101
and 9.0.200. The production harness stays pinned to Node 24.22.1/npm 11.19.1; alternate
versions are qualification fixtures, not a global nvm switch. Existing real npm and
NuGet reuse tests and both selected repository acceptance flows remain required.
The fixture deliberately loads native code; an echoed success marker cannot replace
the SQLite query or the actual ABI loader error.
